01En línea

flowyn · FAE SKIN

Tienda completa de un producto: catálogo, cuenta, carrito sincronizado entre dispositivos y cierre de pedido, con el precio recalculado siempre en el servidor.

La decisión

La clienta no puede crear pedidos, y esa es la parte importante del esquema. Un pedido nace en una función de servidor que recalcula el total desde el catálogo; si el navegador pudiera escribir en esa tabla, cualquiera con la consola abierta se registraría un frasco por mil pesos.

La pasarela de pagos la descarté a mitad: simular un cobro me parecía peor que no tenerlo. Prefiero un no honesto a un sí simulado.

02En línea

La Mesa

Sistema completo de pedidos para un restaurante: app móvil, panel de cocina y backend, con los permisos aplicados en la base de datos y no en la interfaz.

La decisión

Los disparadores de negocio corrían con los permisos de quien lanzaba la actualización: cuando cocina marcaba un pedido como entregado, la seguridad a nivel de fila rechazaba el registro de puntos y el cambio de estado entero fallaba en silencio. Pasarlos a security definer lo resolvió.

Me dejó una regla que aplico desde entonces: los permisos se prueban suplantando a cada rol, nunca desde la cuenta de administrador — ahí todo funciona siempre.

0359 pruebas

frankfurter-ts

Cliente de tipos de cambio para npm: caché que respeta el Cache-Control del servidor, reintentos con espera creciente y aritmética exacta.

La decisión

0.1 + 0.2 no da 0.3 en ningún lenguaje con coma flotante. En un ejercicio da igual; cuando el número es el dinero de alguien, no. Los importes se guardan como enteros en unidades mínimas con BigInt y solo se redondea una vez, al final y de forma explícita.

Es más trabajo y no se ve desde fuera — hasta que las cuentas cuadran al céntimo.

  • BigInt
  • Vitest

04Sin servidor

Panel de divisas

Cinco monedas latinoamericanas frente al euro con datos de 98 bancos centrales. Abre al instante: no hay backend que despertar.

La decisión

Nunca dos ejes Y. El peso colombiano ronda 3.600 por euro y el dólar 1,15: juntarlos con dos escalas inventa una correlación que no está en los datos. Van indexados a 100 sobre un solo eje, y la pregunta que responde el gráfico pasa a ser la interesante.

Mi primera prueba concluyó que la API tenía CORS cerrado y casi cambio la arquitectura por eso. Era un falso negativo: fetch desde Node no manda cabecera Origin. Ahora mido dos veces antes de decidir.

0546 pruebas

API de postulaciones

API REST con autenticación real, historial completo de cada candidatura y estadísticas de tiempo de respuesta.

La decisión

Lo fácil es una columna estado que se sobrescribe, y pierde el historial: sin saber cuándo cambió no hay forma de responder «cuánto tardan de media en contestarme». Cada cambio es un evento y el estado actual es una consulta.

Para comprobar que las pruebas de permisos servían de algo, borré a propósito el filtro de usuario de dos rutas: la batería se puso roja en esas dos y solo en esas.

06Accesible con teclado

Gestor de candidaturas

El tablero que consume esa API: arrastrar y soltar, métricas y estados de error diseñados.

La decisión

El arrastrar y soltar nativo de HTML no funciona con teclado, y mover una tarjeta es la acción de esta pantalla. Usé una librería con soporte de teclado y además cada tarjeta lleva un selector de estado: arrastrar es la vía rápida, no la única.

Por dentro, el refresco del token es una sola promesa compartida. Sin eso, tres peticiones caducadas a la vez lo rotan tres veces y expulsan al usuario sin motivo.

Cómo trabajoCon ejemplos, no con adjetivos

Cualquiera puede decir que es meticuloso.

Estas cuatro están en el código, se pueden abrir y se pueden comprobar. Es la única forma de que signifiquen algo.

  • Los permisos viven en la base de datos

    No en un if de la interfaz, que cualquiera se salta con la consola abierta. En La Mesa y en flowyn van con seguridad a nivel de fila, y en la API el filtro de usuario va dentro del WHERE: la fila que no es tuya no llega ni a salir de PostgreSQL. Además respondo 404 y no 403 cuando el recurso es de otro, porque un 403 confirmaría que existe.

    La Mesa · flowyn · API de postulaciones

  • Pruebo contra la base de datos de verdad

    105 pruebas automáticas que corren en cada cambio, contra PostgreSQL real y sin dobles: las restricciones que protegen los datos viven en la base, y un mock devuelve lo que yo le diga. Y para saber que las pruebas sirven, las rompo a propósito y compruebo que se ponen rojas donde deben.

    API de postulaciones · frankfurter-ts

  • El camino que falla también está diseñado

    Reintentos con espera creciente, datos en caché servidos y marcados cuando la fuente no responde, pantallas de error con su botón de reintentar y cambios optimistas que se deshacen solos si el servidor los rechaza. Lo que hace que una aplicación se sienta sólida no es el camino bueno, es el otro.

    frankfurter-ts · Panel de divisas · Gestor

  • La accesibilidad la mido, no la prometo

    17 de 17 pares de color verificados contra WCAG AA por un script propio que corre en cada despliegue, paleta de gráficos validada bajo daltonismo, tablero que se maneja entero con teclado y tabla alternativa bajo cada gráfico. Todo comprobable, ninguna promesa.

    flowyn · Panel de divisas · Gestor
